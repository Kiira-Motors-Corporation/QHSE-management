Set up test users by role

Create three test accounts in the test realm, give each access through a role-bearing group, then sign in as each person to confirm the right HWMS screens appear.

Before you start gateway client is ready Realm test Accounts 1 per role
FirstConfirm roles
SecondCreate groups + map roles
ThirdCreate users + add to groups
The client is ready; leave its settings alone.

These steps only create groups and test accounts. Do not change the gateway client secret, redirect URIs, or other client settings as part of this task.

Important for this HWMS build: use Realm roles.

The gateway checks roles in the token's realm_access.roles claim. A client role usually appears under resource_access instead and may not authorize the user. If step 4 created client roles, pause and confirm that the deployed gateway has been configured to accept them; otherwise create/use the matching Realm roles before continuing.

1

Open the correct realm and confirm roles

Do not create these test accounts in master or the local hwms realm.

  1. Sign in to the Keycloak Admin Console using your administrator account.
  2. Use the realm selector in the upper-left / top navigation to select test. Re-check the realm name before creating anything.
  3. Open Realm roles in the left navigation. Confirm these exact role names are listed:

If the roles were created under Clients → hwms-gateway → Roles, treat that as a stop-and-verify point (see the warning above) rather than assigning them blindly.

2

Create one group for each role

Assign the role to the group once. Every member then inherits it.

  1. In the left navigation, open Groups → Create group.
  2. Enter HWMS Managers and select Create.
  3. Open the new group, then select its Role mapping tab → Assign role.
  4. Choose Realm roles (some Keycloak versions call the filter “Filter by realm roles”), select hwms-manager, and click Assign.
  5. Repeat the same steps for HWMS Officers → hwms-officer and HWMS Directors → hwms-director.
Check before moving on

Open each group's Role mapping tab and confirm it shows exactly its matching HWMS role. Keep these three test groups separate; do not combine the roles in one group.

3

Create the three test accounts

Use unique usernames and email addresses permitted by your test realm. Do not use a real employee's identity for a test account.

  1. Left navigation → Users → Add user (or Create new user).
  2. Complete the fields below. Keep the account Enabled.
  3. Select Create, then open the new user and add the matching group using the Groups tab → Join group (or Join Groups) → choose the group → Join.
  4. Repeat for the other two users. If a username or email already exists, use a unique test address approved for the realm; do not overwrite another account.

4

Set a temporary password for each user

Set the password individually from each user's credentials page.

  1. Open the user → Credentials → Set password.
  2. Enter the temporary password twice. Follow the password policy configured for the test realm; if rejected, use the validation message to correct it.
  3. Leave Temporary switched On, choose Save, then confirm Set password if prompted.
  4. Give each tester their initial password securely. The user must choose a new password at the first successful login.
Credential safety

Never put passwords, client secrets, or copied access tokens in source control, this guide, or chat. Use a password manager or another approved secure channel; avoid reusing real staff passwords.

5

Verify group membership and inherited role

Do this for all three accounts before attempting sign-in.

  1. Open a user → Groups. Confirm only the intended test group is listed.
  2. Open Role mapping. Turn off Hide inherited roles (if shown) and confirm the role arrives through the group.
  3. Make sure no test user has been directly assigned another HWMS role. A person in multiple HWMS groups could get a broader combination of access.

6

Sign in as each user and check access

Use the HWMS application only after it has been configured to authenticate against the test realm.

  1. Open a private/incognito browser window and go to the HWMS application sign-in page.
  2. Sign in as hwms.test.officer using its temporary password. Complete the forced password change, then confirm the expected pages.
  3. Sign out fully, close that private window, and repeat for the manager and director. This prevents a prior Keycloak SSO session from hiding which account is being tested.
